## Integration and material limits

Root still owns the actual lifecycle adapter and all runtime/helper/title/extractor wiring. Translate engine attempt identities/features into conservative bounds, inherit exact execution context, reserve before wire, propagate terminal denial, settle observed/unknown usage faithfully and persist verified retry/reset eligibility. Byte counts alone do not provide token bounds. Fresh source receipts must populate the verified cache/authorization mapping before refreshProof or source acquisition can pass. New source authorization/incarnation/scope requires putGrant/revoke; ordinary short receipt renewal uses refreshProof. Source adapter assembly/hash/query validation remains independent.

Background areas remain disabled/setup incomplete unless explicitly configured. Wi-Fi/battery preferences and cadence are persisted inputs for the future finite worker; no scheduling or device constraint enforcement occurs here. Frequencies are best effort. Global/background windows must be configured explicitly; no daily reset is guessed. Foreground rows survive restart conservatively until recovery explicitly ends an abandoned execution. One common configured monetary currency/micro-unit must be enforced by the trusted tariff validator.

Retrieval is field/source/evidence targeted and character bounded; the runtime must also enforce actual model token budgets and revalidate before dispatch. Global learning fences conservatively cancel all unfinished jobs on authorization/correction/exclusion changes. Ambiguous canonical acquisition can be suspended broadly; unmapped free-text exclusions block automated acquisition rather than pretending semantic matching. Immutable source revision/snapshot identity belongs in periodKey for mutable records, keeping recordKey canonical for forgetting. An identical grant/record/period key deduplicates without overwriting previously supporting evidence. Terminal unknown settlements remain conservative; automatic later refinement is not provided.

No live billing/model/authentication behavior, native visual behavior, scheduling or integrated runtime acceptance is established by these local fixtures.
